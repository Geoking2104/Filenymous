# Feuille de route Filenymous

| Fonctionnalité | Effort | Cible | Valeur ajoutée | Statut |
|---|---|---|---|---|
| Secrets Vault | Faible | Dev & IT | Partage de mots de passe et clés API à lecture unique, la clé ne quitte jamais le navigateur | ✅ Livré |
| Mode WebRTC P2P | Élevé | Tous | Transfert direct chiffré de bout en bout, sans stockage serveur | ✅ Livré |
| Dropzone de collecte | Moyen | PME, indépendants | Recevoir des fichiers de n'importe qui sans compte, avec mot de passe et expiration | ✅ Livré |
| CLI DevOps (CI/CD) | Moyen | DevOps, équipes CI | `npx filenymous upload app.zip --ttl 1h` : 100 % pair-à-pair, liens éphémères (TTL, N téléchargements), webhooks, `filenymous receive`. Voir [cli/README.md](../cli/README.md) | ✅ Livré (CLI) — API REST hébergée : non prévue (pas de stockage serveur) |
| Extension navigateur (Chrome / Firefox) | Moyen | Tous, Dev & IT | Partage en 2 clics par clic droit, sans ouvrir le site : texte sélectionné → lien secret à lecture unique (coffre, chiffré dans l'extension) ; image, vidéo, son ou fichier d'un lien → transfert direct P2P ; lien copié aussitôt dans le presse-papier, notification et badge d'état. Fenêtre avec glisser-déposer, mot de passe et durée. Le navigateur doit rester ouvert jusqu'au téléchargement des fichiers (comme la CLI). Voir [extension/README.md](../extension/README.md) | 🟡 En revue (PR) — publication Chrome Web Store / AMO et redéploiement du relais (origines d'extension) à faire |
| Espace Client-Prestataire | Faible (réutilise la Dropzone) | Avocats, comptables, freelances | Une Dropzone par projet pour collecter les documents confidentiels des clients, sans infrastructure | 🟠 Pro (via Dropzone) |
| Canal de signalement (lanceurs d'alerte) | Élevé | Journalistes, conformité, audit interne | Boîte asynchrone : clés ECDH P-256 générées dans le navigateur de l'organisation (clé privée dans un fichier chiffré par phrase de passe, jamais envoyée), signalements scellés à la clé publique (ECDH éphémère + HKDF + AES-256-GCM) et stockés chiffrés 90 jours sur le VPS ; métadonnées EXIF/GPS, PNG/WebP et propriétés PDF retirées dans le navigateur, avec avertissement par fichier sinon ; clé de suivi sans e-mail (statut, réponses chiffrées, compléments) ; aucune IP enregistrée par l'application (limites de débit sur HMAC tournant en mémoire), `access_log off` côté nginx. Pensé pour la directive européenne sur les lanceurs d'alerte et la loi Sapin II (intention de conception) | ✅ Livré (PR en revue ; redéploiement du relais requis) |
| Partage streamé | Moyen | Vidéastes, studios, podcasteurs | Lecture vidéo/audio pendant le transfert : requêtes de plages sur le canal P2P + Service Worker (Range HTTP), avance rapide, enregistrement possible, mêmes blocs AES-GCM. **Protection de revue** (agences/marques) : mot de passe + expiration (1 h, 24 h, 7 j ou date) liée au lien et à la clé AES, compte à rebours, arrêt du lecteur à l'expiration. CLI : `--stream`, `--expires` | ✅ Livré |

Notes :
- Le canal de signalement ne cache pas l'adresse IP de l'utilisateur au réseau ; pour cela, utiliser Tor Browser. Filenymous ne l'enregistre pas, mais le fournisseur d'accès, le réseau de l'employeur et l'hébergeur en amont peuvent la voir.
- Canal de signalement : la perte du fichier de clé ou de sa phrase de passe rend les signalements définitivement illisibles (pas de récupération possible).
- Aucune conformité (RGPD, NIS2, ISO 27001) n'est revendiquée tant qu'un audit n'a pas eu lieu.
- La CLI nécessite la version du relais qui accepte les clients sans en-tête Origin (PR CLI) ; à redéployer via le workflow openDPE avant usage en production.
- L'extension navigateur nécessite la version du relais qui accepte les origines `chrome-extension://*` / `moz-extension://*` dans `ALLOWED_ORIGIN` (PR extension) ; à redéployer via le workflow openDPE avant usage en production.
